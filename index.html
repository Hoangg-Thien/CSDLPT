🗺️
Kiểm thử chức năng định tuyến (Routing)
Đảm bảo xác định đúng vùng miền NORTH/SOUTH
5 TC
Mã TC Chức năng Mục tiêu kiểm thử Kết quả mong đợi Code
ROUTE-01 Định tuyến theo tỉnh thành Chọn đúng database miền Bắc (Hà Nội, Hải Phòng) hoặc miền Nam (Hồ Chí Minh, Cần Thơ). Xác định region=NORTH hoặc region=SOUTH, người dùng kết nối đúng DB vùng. 200
ROUTE-02 Xử lý lỗi Từ chối yêu cầu khi tỉnh không hợp lệ hoặc không hỗ trợ. Trả lỗi rõ ràng, thông báo tỉnh chưa được hỗ trợ. 400
ROUTE-03 Định tuyến theo GPS Xác định vùng miền theo tọa độ GPS hợp lệ. Trả region đúng theo vị trí địa lý của tọa độ. 200
ROUTE-04 Xử lý lỗi GPS thiếu thông tin (chỉ latitude hoặc longitude). Yêu cầu cung cấp đủ latitude + longitude. 400
ROUTE-05 Xử lý xung đột Region và province mâu thuẫn (region=NORTH nhưng province=Ho Chi Minh). Không cho phép xử lý tiếp, báo mâu thuẫn dữ liệu. 400
⚡
Kiểm thử cơ chế dự phòng (Failover)
Chuyển read-only và phục hồi ghi
4 TC
Mã TC Chức năng Mục tiêu kiểm thử Kết quả mong đợi Code
FAIL-01 Chuyển sang chế độ đọc Primary ngưng hoạt động, đọc dữ liệu từ Replica. Vẫn truy vấn được dữ liệu ở READ-ONLY. 200
FAIL-02 Chặn thao tác ghi Primary ngưng hoạt động, thao tác ghi bị chặn. Trả mode: READ_ONLY khi cố ghi. 503
FAIL-03 Phục hồi chức năng Primary hoạt động trở lại, cho phép ghi dữ liệu. Tạo ride thành công, hệ thống về PRIMARY. 200
FAIL-04 Xử lý sự cố nghiêm trọng Cả Primary và Replica đều ngưng hoạt động. Không đọc/ghi được, thông báo dịch vụ gặp sự cố. 503
📡
Kiểm thử API trạng thái hệ thống
/api/system/status cung cấp mode + active node
2 TC
Mã TC Chức năng Mục tiêu kiểm thử Kết quả mong đợi Code
SYS-01 Trạng thái bình thường Primary đang chạy, hệ thống hoạt động ổn định. mode=PRIMARY, activeNode=PRIMARY. 200
SYS-02 Trạng thái dự phòng Primary gặp sự cố, hệ thống chạy trên Replica. mode=READ_ONLY, activeNode=REPLICA. 200
🖥️
Kiểm thử giao diện quản trị (Admin Dashboard)
Dashboard, Trips, Drivers, Users
4 TC
Mã TC Chức năng Mục tiêu kiểm thử Kết quả mong đợi Loại
ADMIN-01 Trang tổng quan Hiển thị đúng số liệu thống kê tổng quan. Số Users/Drivers/Trips khớp dữ liệu API. UI
ADMIN-02 Quản lý chuyến đi Phân nhóm chuyến theo vùng và status đúng. Danh sách SOUTH/NORTH rõ ràng, status hiển thị đúng. UI
ADMIN-03 Quản lý tài xế Phân nhóm theo vùng, trạng thái sẵn sàng/bận. isAvailable hiển thị Available/Busy chính xác. UI
ADMIN-04 Quản lý người dùng Phân nhóm người dùng theo vùng miền. Users chia SOUTH/NORTH rõ ràng. UI
📱
Kiểm thử ứng dụng di động (Mobile App)
Select user, DB status, book ride, history
5 TC
Mã TC Chức năng Mục tiêu kiểm thử Kết quả mong đợi Loại
APP-01 Chọn người dùng Load danh sách users, cho phép chọn user. Current user và region hiển thị chính xác. UI
APP-02 Hiển thị trạng thái DB Badge status theo /system/status. PRIMARY (xanh), REPLICA (vàng), Offline (đỏ). UI
APP-03 Đặt xe bình thường Primary hoạt động bình thường. Chuyển sang màn hình driving, tạo ride thành công. UI
APP-04 Chặn đặt xe khi sự cố Primary gặp sự cố. Nút đặt xe disable, không tạo ride mới. UI
APP-05 Xem lịch sử Hệ thống ở chế độ chỉ đọc. Hiện rõ đang đọc từ Replica, list vẫn đầy đủ. UI
Ghi chú
  • • Mỗi test case kiểm tra một khía cạnh cụ thể của hệ thống.
  • • Kết quả mong đợi mô tả chi tiết để so sánh với thực tế.
  • • Bao quát cả trường hợp thành công và xử lý lỗi.
  • • Nên kiểm thử theo thứ tự từng nhóm chức năng để dễ kiểm soát.
